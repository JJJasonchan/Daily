# Daily：macOS 每日任务与提醒应用设计规格

## 1. 产品概述

Daily 是一个原生 macOS 每日任务应用，面向只需要“查看今天、完成勾选、到点提醒”的个人用户。应用同时支持主窗口和菜单栏快速面板，完全离线运行，不需要账号、网络或服务端。

核心体验：

1. 用户打开应用即可看到今天的全部任务。
2. 任务不按固定任务、临时任务分组，统一显示和排序。
3. 用户可以勾选完成，也可以快速添加当天任务。
4. 任务可以仅执行一次，也可以按规则重复。
5. 未完成的单次任务自动顺延；重复任务每天产生独立记录。
6. 用户可以查看每天的完成情况和任务明细。

## 2. 目标与非目标

### 2.1 首版目标

- 创建、编辑、删除和拖动排序任务。
- 在一个统一列表中展示当天所有有效任务。
- 支持单次任务和重复任务。
- 支持每日统一提醒，以及每个任务独立提醒。
- 支持提醒一次和持续提醒。
- 支持单次任务自动顺延。
- 记录每天的完成状态并计算完成率。
- 从菜单栏查看、勾选和快速添加任务。
- 所有数据只保存在当前 Mac。

### 2.2 首版非目标

- 不提供账号、云同步或多设备同步。
- 不提供团队协作、任务分配或共享清单。
- 不提供项目、标签、优先级、子任务和附件。
- 不提供自然语言日期解析。
- 不提供 iPhone、iPad、Windows 或 Web 客户端。
- 不接入 Apple 提醒事项作为数据源。
- 不提供复杂生产力报表、积分或连续打卡奖励。

## 3. 市场调研结论

| 产品 | 相关能力 | 对 Daily 的启发 |
| --- | --- | --- |
| [Apple 提醒事项](https://support.apple.com/guide/reminders/add-dates-or-locations-to-reminders-remnd4b206fb/mac) | Today、重复规则、时间和地点通知、系统同步 | 系统整合完善，但设置和组织能力超过本产品所需范围 |
| [Things](https://culturedcode.com/things/features/) | Today、重复任务、时间提醒、日历事件和快捷录入 | 主窗口应重视今日焦点和快捷操作，但不复制完整 GTD 结构 |
| [Todoist](https://www.todoist.com/features) | Today、复杂重复日期、跨平台同步和自然语言 | 重复规则有价值，项目和协作体系不属于首版范围 |
| [TickTick](https://ticktick.com/mac) | 侧边栏、今日列表、快速添加、拖放、键盘命令和菜单栏面板 | 作为整体信息架构与操作效率参考，但不复制品牌配色或完整功能体系 |
| [Due](https://www.dueapp.com/support/osx/fine-tuning-reminders.html) | 到期后自动再次提醒，直到完成、推迟或关闭 | 持续提醒是明确的任务级选项，并在任务完成后立即停止 |
| [Streaks](https://streaksapp.com/) | 每日任务、完成统计和跨 Apple 平台支持 | 每日任务体验应直接，但产品不以连续打卡作为核心激励 |

市场中的成熟产品普遍加入项目管理、日历、协作或习惯体系。Daily 的差异不是更多功能，而是统一的今日列表、低操作成本、可靠提醒和清晰的跨日规则。

## 4. 产品结构

### 4.1 主窗口

侧边栏包含四个入口：

- 今日
- 重复规则
- 历史记录
- 设置

“今日”是默认页面，包含：

- 当前日期
- 已完成数量、总任务数量和完成率
- 一条简洁的完成进度条
- 当天全部任务组成的统一列表
- 添加任务入口

列表不根据任务来源分组。任务默认按照用户手动顺序排列，允许拖动调整。任务行可以显示提醒时间；自动顺延的单次任务可以显示“已顺延 N 天”的轻量状态。

已完成任务保留在当日列表中并降低视觉权重。勾选状态改变后，主窗口、菜单栏面板和完成率立即更新。

### 4.2 菜单栏面板

菜单栏面板与主窗口使用相同的当日数据，包含：

- 今日完成数量和进度条
- 全部当日任务
- 勾选完成操作
- 快速添加输入框
- 打开主窗口入口

菜单栏面板不提供重复规则、提醒高级设置或历史详情。复杂操作统一在主窗口完成。

### 4.3 重复规则页面

该页面管理所有启用和停用的重复任务模板。用户可以：

- 新建重复任务
- 修改标题、重复频率和提醒
- 启用或停用模板
- 调整模板的默认排序位置
- 删除模板

删除模板不删除历史记录。修改模板不改写已经归档的日期。

### 4.4 历史记录页面

历史页按周展示每天的完成数量和完成率。选择某一天后显示当天出现过的全部任务，以及每项任务的最终状态：

- 已完成
- 未完成
- 已顺延至下一天

完成率计算公式为：当天已完成任务数量除以当天出现过的任务总数。当天没有任务时不显示百分比，状态为“无任务”。

## 5. 任务创建与编辑

### 5.1 基础字段

任务名称是唯一必填项。新任务默认值为：

- 执行规则：仅今天
- 提醒：关闭
- 排序位置：当前列表末尾

### 5.2 执行规则

用户可以选择：

- 仅今天
- 重复执行

首版重复频率支持：

- 每天
- 每个工作日，即周一至周五
- 每周指定一个或多个星期

重复规则包含开始日期。首版不支持结束日期、每月、每年或基于完成时间的重复。

任务保存后统一进入今日列表；列表不显示“单次”或“重复”分类标签。

### 5.3 提醒规则

应用支持两个提醒层级：

1. 每日统一提醒：在设置中选择每天的提醒时间，用于提示用户查看今日清单。
2. 任务独立提醒：每项任务可以设置具体时间和提醒方式。

任务提醒方式包括：

- 关闭
- 提醒一次
- 持续提醒

持续提醒默认每 15 分钟触发一次，直至任务完成、提醒关闭或任务删除。用户可以在设置中调整全局持续提醒间隔；首版支持 5、10、15、30 和 60 分钟。

当提醒时间已经过去后再创建或编辑任务：

- “提醒一次”不补发已经错过的通知。
- “持续提醒”从保存后的下一个提醒间隔开始通知。

完成任务时必须立即取消该任务尚未触发的全部本地通知。

### 5.4 编辑与删除语义

- 编辑单次任务只修改当前有效实例及其来源信息。
- 编辑重复任务的标题或提醒时，更新今天尚未完成的实例和未来实例；今天已经完成的实例保持不变。
- 在今日列表删除单次任务时，删除当前实例并停用其来源，不再顺延；过去记录保持不变。
- 在今日列表删除重复任务时提供“仅移除今天”和“停止以后重复”两个明确操作。前者只移除当天实例，后者同时停用模板。
- 当天被删除或仅移除的任务不计入当天完成率；已经归档的历史日期只读，不能补勾或删除。

## 6. 跨日处理

应用以系统当前日历、时区和本地日期作为日期边界。跨日切换必须是幂等操作，同一天重复执行不会重复生成任务。

检测跨日的时机包括：

- 应用启动
- 应用从休眠或后台重新激活
- 系统日期、时间或时区发生变化
- 应用运行期间跨过午夜

进入新日期时依次执行：

1. 冻结上一天的任务完成状态。
2. 为未完成的单次任务生成当天顺延实例。
3. 按启用的重复规则生成当天实例。
4. 合并实例并保证同一来源在当天只出现一次。
5. 安排当天尚未错过的通知。

### 6.1 单次任务

未完成的单次任务每天自动顺延，直到完成或删除。顺延实例保留：

- 原始任务标识
- 原始创建日期
- 上一日实例标识
- 已顺延天数

任何时刻只保留一份当前有效的顺延实例，避免应用多日未运行后生成多份相同任务。

### 6.2 重复任务

重复任务每天根据规则生成新的当日实例。前一天未完成的重复任务不额外顺延，避免新实例和旧实例同时出现。历史页仍保留前一天的未完成状态。

修改重复规则时：

- 过去日期不变。
- 当天实例尚未完成时同步最新标题、提醒和启用状态。
- 当天实例已经完成时保持原记录不变，新规则从下一个匹配日期生效。

## 7. UI 视觉与动效

### 7.1 TickTick 参考边界

整体 UI 参考 TickTick for Mac 的桌面任务工作流：

- 左侧固定导航，中央区域突出当前任务列表。
- 今日视图直接呈现任务，保持较高信息密度。
- 新任务始终有清晰、低成本的快速添加入口。
- 支持鼠标拖动排序、方向键导航和常用键盘快捷操作。
- 菜单栏面板承担随手查看、完成和录入。
- 选中任务后使用临近任务的浮层或检查器编辑，不强制跳转页面。

不采用 TickTick 的多列表、彩色背景、日历排程、标签和三栏详情体系。Daily 保持“侧边栏 + 统一今日列表”的两层结构，也不复制 TickTick 的图标、配色、尺寸或视觉资产。

### 7.2 黑白视觉系统

- 外观跟随 macOS 浅色和深色模式。
- 黑、白和中性灰构成主要界面色彩，不设置品牌强调色。
- 完成进度在浅色模式使用黑色，在深色模式使用白色。
- 警告和错误可以使用 macOS 系统语义色，但必须同时配合图标和文字，颜色不是唯一提示。
- 使用 SF Pro 系统字体；标题通过字号和字重建立层级，不依赖彩色标签。
- 任务行目标高度为 44–48 pt，保持 TickTick 式紧凑列表感，同时满足可点击范围。

### 7.3 原生 Liquid Glass

最低系统版本为 macOS 26，直接使用 SwiftUI 原生 Liquid Glass：

- 自定义模块使用 `glassEffect(_:in:)`，交互模块启用 `Glass.interactive()`。
- 相邻玻璃模块放入 `GlassEffectContainer`，减少重复渲染并支持形状融合。
- 新增、展开和合并模块时使用 `glassEffectID` 与匹配几何关系产生材质形变。
- 侧边栏、菜单栏面板、任务编辑器、浮动按钮和任务行均可使用玻璃模块。
- 同一层级的多个任务行共用容器，不在玻璃表面继续叠加浅色玻璃，避免折射混浊。

玻璃表面包含三层视觉信息：

1. 背景模糊与环境色折射。
2. 沿统一左上方虚拟光源形成的边缘高光。
3. 随悬停、按下和拖动增强的内部光泽。

静止状态保持克制，交互时增强反射和形变。正文文本始终位于足够清晰的前景层，玻璃效果不能牺牲任务名称和提醒时间的对比度。

### 7.4 动效语言

“线性”指运动路径直接、方向明确，不使用匀速 `linear` 时间曲线。所有可交互动画必须可中断，并从当前屏幕状态继续运动。

| 场景 | 动效规则 |
| --- | --- |
| 普通移动与状态变化 | 无过冲弹簧，阻尼比约 1.0，响应约 0.32–0.4 秒 |
| 拖动释放、浮层展开 | 轻微回弹，阻尼比约 0.8，响应约 0.3–0.4 秒 |
| 按钮与任务按下 | 指针按下立即缩放至约 0.97，松开后弹性恢复 |
| 拖动排序 | 任务与指针 1:1 移动，保留抓取偏移；相邻任务连续让位 |
| 勾选完成 | 完成环、文字状态、任务材质和顶部进度在同一交互中联动 |
| 浮层出现 | 从触发控件的位置展开，缩放、透明度和玻璃强度同步变化 |
| 浮层关闭 | 沿出现路径返回触发位置，不改变退出方向 |

拖动结束时将手势速度传递给弹簧。动画执行期间不锁定输入，用户可以抓住正在移动的任务或面板并反向操作。持续循环装饰动画不进入首版。

### 7.5 交互反馈

- 指针按下时立即响应，不等到鼠标松开。
- 悬停任务时提升边缘亮度和内部折射光泽，位移不超过 2 pt。
- 完成任务后提供撤销入口，不使用阻塞式确认框。
- 删除重复任务只有在选择“停止以后重复”时显示明确确认。
- 拖动超过列表边界时使用渐进阻力，不产生硬停止。
- 系统支持的声音反馈只用于提醒；普通勾选、悬停和排序不播放声音。

### 7.6 动效与材质可访问性

- 开启“减少动态效果”时，去除位移、惯性和弹性过冲，改为短交叉淡化与即时重排。
- 开启“降低透明度”时，将玻璃模块切换为高不透明度黑白表面并保留明确边框。
- 开启“增强对比度”时，提高文字、边缘和选中状态对比度。
- 键盘焦点必须有独立轮廓，不能只通过玻璃亮度表达。
- 所有交互保持 VoiceOver 标签、完整键盘导航和足够点击区域。

## 8. 技术架构

### 8.1 技术选型

- UI：SwiftUI
- 本地持久化：SwiftData
- 通知：UserNotifications
- 应用形态：普通主窗口和 `MenuBarExtra`
- 最低系统版本：macOS 26
- 网络依赖：无

选择 macOS 26 是为了直接使用 SwiftUI 原生 `glassEffect`、`GlassEffectContainer`、交互式玻璃和材质形变，不维护旧系统的模拟毛玻璃兼容层。

### 8.2 组件边界

#### UI Layer

负责主窗口、菜单栏面板、表单和状态展示。UI 只通过服务接口修改数据，不直接实现跨日或通知算法。

#### TaskService

负责：

- 创建、编辑和删除任务
- 完成和取消完成
- 调整排序
- 查询今日列表
- 维护模板与实例之间的关系

#### DayRolloverService

负责：

- 判断是否需要跨日处理
- 归档上一日状态
- 顺延单次任务
- 生成重复任务实例
- 保证生成过程幂等

#### NotificationService

负责：

- 请求和读取通知权限
- 安排每日统一提醒
- 安排一次任务提醒
- 展开有限数量的持续提醒通知
- 完成、编辑或删除任务时取消旧通知
- 日期、时间或时区改变后重建未来通知

#### Persistence Layer

通过 SwiftData 存储模板、每日实例和设置。服务层依赖协议而不是具体容器，方便使用内存仓库进行单元测试。

## 9. 数据模型

### 9.1 TaskTemplate

用于保存可重复任务的长期定义，也作为单次任务的来源信息。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | UUID | 稳定标识 |
| title | String | 任务名称 |
| kind | once / recurring | 单次或重复 |
| recurrence | 可空结构 | 重复频率、星期集合和开始日期 |
| reminderMode | none / once / persistent | 提醒方式 |
| reminderTime | 可空时间 | 当地时区中的时分 |
| sortIndex | Double | 默认排序位置 |
| isEnabled | Bool | 是否继续生成实例 |
| createdAt | Date | 创建时间 |
| updatedAt | Date | 最近修改时间 |

### 9.2 DailyTask

代表某一天列表中的一个实际任务。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | UUID | 实例标识 |
| templateID | UUID | 来源模板 |
| localDay | 日期键 | 所属本地日期，不包含时间 |
| titleSnapshot | String | 当天显示的标题快照 |
| reminderSnapshot | 可空结构 | 当天提醒配置快照 |
| sortIndex | Double | 当天排序位置 |
| completedAt | 可空 Date | 完成时间 |
| rolloverOriginID | 可空 UUID | 上一顺延实例 |
| originalCreatedDay | 日期键 | 原始任务创建日期 |
| rolloverCount | Int | 已顺延天数 |
| createdAt | Date | 实例创建时间 |

`templateID + localDay` 对重复任务构成逻辑唯一键；顺延任务通过原始任务标识和当日日期保证唯一。

### 9.3 AppSettings

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| dailyReminderEnabled | Bool | 是否启用每日统一提醒 |
| dailyReminderTime | 可空时间 | 每日统一提醒时间 |
| persistentIntervalMinutes | Int | 持续提醒间隔 |
| lastProcessedLocalDay | 可空日期键 | 最近完成跨日处理的日期 |

通知授权状态从系统实时读取，不作为业务真相长期保存。

## 10. 通知调度策略

macOS 本地通知数量可能受到系统限制。持续提醒不一次性安排无限通知，而是采用滚动窗口：

- 每个持续提醒任务最多预先安排接下来 8 次通知。
- 应用启动、激活、任务编辑或任务完成时重新同步窗口。
- 通知标识由任务实例 ID、提醒模式和触发序号组成，保证可精确取消。
- 如果应用长时间未运行，系统只保证已安排窗口内的通知；下次激活时继续补充。

每日统一提醒使用独立标识。关闭统一提醒或修改时间时，先取消旧请求，再安排新请求。

## 11. 异常与边界处理

### 11.1 通知权限被拒绝

任务管理功能继续可用。任务编辑页和设置页明确显示通知不可用，并提供打开 macOS 系统设置的入口。应用不反复弹出授权请求。

### 11.2 应用多日未运行

启动时按日期顺序补做跨日处理。重复规则在每个错过的日期生成历史实例并记为未完成；单次任务只在最终当天保留一份有效顺延实例，中间日期记录为已顺延。整个过程可重复执行且结果相同。

### 11.3 系统时间或时区变化

收到系统时间变化通知后重新计算当前本地日期。如果日期边界变化，执行幂等跨日处理；随后取消并重建未来通知。

### 11.4 保存失败

表单保留用户当前输入，显示可重试错误。完成勾选只有在持久化成功后才更新为最终状态，避免界面成功但数据丢失。

### 11.5 任务编辑与通知冲突

编辑标题、提醒时间或提醒方式时，先保存数据，再取消旧通知并安排新通知。通知同步失败不回滚任务数据，但界面显示提醒未成功安排，并允许重试。

## 12. 测试与验收

### 12.1 单元测试

- 每天、工作日和指定星期的规则匹配。
- 同一天重复执行跨日处理不会产生重复实例。
- 单次任务连续多日顺延时始终只有一个当前实例。
- 重复任务未完成时次日不生成额外顺延实例。
- 完成率在完成、取消完成和零任务情况下计算正确。
- 修改重复模板不会改写历史快照。
- 通知标识稳定，可在完成、编辑和删除时精确取消。
- 持续提醒滚动窗口的次数和间隔正确。
- 时区变化后日期键和通知时间重新计算正确。

### 12.2 集成测试

- SwiftData 内存容器中的模板、实例和设置可以完整读写。
- 主窗口与菜单栏对同一数据变更实时更新。
- 应用从前一天数据恢复时正确生成今天列表。
- 通知权限允许、拒绝和未决定三种状态的界面反馈正确。

### 12.3 手动验收

- 可以创建、编辑、删除和拖动排序任务。
- 今日列表不区分固定任务和临时任务。
- 菜单栏可以完成任务并快速添加新任务。
- 单次任务跨日自动顺延并增加顺延天数。
- 重复任务每天只出现一次。
- 一次提醒只触发一次。
- 持续提醒按照设置间隔触发，完成后停止。
- 每日统一提醒按设定时间触发。
- 历史页正确显示每天完成率和任务状态。
- 关闭并重新打开应用后数据和当日状态保持一致。
- 主窗口、任务模块和菜单栏使用原生 Liquid Glass，并具有可辨认的光泽折射。
- 悬停、按下、拖动、勾选和浮层切换符合动效规则，过程中可以被新输入中断。
- “减少动态效果”“降低透明度”和“增强对比度”开启后界面仍可完整操作。

## 13. 成功标准

首版成功标准不是功能数量，而是以下完整路径稳定可用：用户在主窗口或菜单栏添加任务，按需设置重复和提醒，在当天列表中勾选完成；未完成单次任务次日自动出现，重复任务按规则生成；历史页能够准确解释每天完成了什么、遗漏了什么。
